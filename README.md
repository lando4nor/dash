# Монитор билетов «Грай, [Марку]»

Бот каждые 15 секунд проверяет концерты на myr.com.ua и шлёт уведомление в Telegram,
когда в **первых трёх рядах партера в центре зала** появляются свободные места
или меняется цена на них.

Сайт myr.com.ua продаёт билеты через виджет soldout.ua. Бот читает его открытый API:
список свободных билетов и SVG-схему зала. «Центр» считается по координатам мест на схеме,
поэтому корректно работает и с проходом посередине ряда (Полтава, Одеса), и с дугой (Чернігів).

## Настройка (5 минут)

1. **Создать бота.** В Telegram написать [@BotFather](https://t.me/BotFather) → `/newbot` → получить токен.
2. **Узнать chat_id.** Написать своему боту любое сообщение, затем:
   ```bash
   TELEGRAM_BOT_TOKEN=123:ABC python3 seat_monitor.py --get-chat-id
   ```
   Или просто открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найти `"chat":{"id":...}`.
3. **Добавить секреты в GitHub:** Settings → Secrets and variables → Actions → New repository secret:
   `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
4. **Включить workflow:** вкладка Actions → `seat-monitor` → Run workflow (первый запуск вручную).
   Дальше он работает сам: один запуск опрашивает API каждые 15 секунд почти 6 часов,
   следующий уже стоит в очереди (расписание раз в час) и стартует сразу после него.

При первом запуске придёт сообщение со всеми местами, которые уже свободны в зоне.
Потом — только о новых местах и об изменении цены. Если место купили, а потом оно
снова освободилось (например, бронь истекла), придёт повторное уведомление.

## Настройки — `config.json`

```jsonc
"defaults": {
  "rows": [1, 2, 3],      // какие ряды смотреть
  "center_seats": 20,     // сколько мест в центре ряда считать «центром»
  "max_price": null       // например 1500 — не сообщать о более дорогих
}
```

Любой параметр можно переопределить для конкретного концерта, добавить `"sector"`
(ключ сектора на схеме, по умолчанию партер) или новый концерт по ссылке:
`{"url": "https://myr.com.ua/events/.../tickets"}` — id события бот найдёт сам.

## Запуск локально / на своём сервере

Нужен только Python 3.9+, без зависимостей.

```bash
python3 seat_monitor.py --dry-run -v          # показать зону центра и свободные места, ничего не отправляя
export TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=...
python3 seat_monitor.py --test-telegram       # проверить, что сообщения доходят
python3 seat_monitor.py --loop 15             # проверять каждые 15 секунд
```

## Важно

- Одна проверка — 4 запроса (по одному на концерт, ~130 КБ каждый). Данные концерта и схема
  зала кэшируются на час. Если сайт отвечает ошибками, бот сам увеличивает паузу до 5 минут.
- На стыке двух запусков GitHub Actions бывает пауза в 1–2 минуты (запуск новой машины).
  Для полностью непрерывной работы запустите `--loop 15` на своём компьютере или сервере.
- GitHub отключает расписание в публичном репозитории после 60 дней без коммитов.
  Последний концерт 13.12 — примерно через 63 дня, так что в начале декабря
  стоит сделать любой коммит (или нажать «Enable workflow», если GitHub пришлёт письмо).
- Бот только уведомляет — купить место нужно самому по ссылке из сообщения.
